#### 5.2 Digital Signature Scheme

All acceptances of this Agreement will be recorded using the following digital signature scheme:

| Step | Process |
|------|---------|
| **1. Contribution Submission** | Contributor submits Contribution through Platform interface or Git repository. |
| **2. Identity Verification** | Platform verifies Contributor identity through wallet signature (XMR or Tari) or platform authentication token. |
| **3. Agreement Recording** | Platform creates a cryptographic record of: (a) Contributor identity, (b) Agreement version accepted, (c) Timestamp, (d) Contribution identifier. |
| **4. Blockchain Anchoring** | A hash of the acceptance record is anchored to the Tari blockchain as an immutable contribution certificate. |
| **5. Receipt Issuance** | Contributor receives a digitally signed receipt via email and Platform notification. |

#### 5.3 Acceptance Record Format

Each acceptance record will contain:
```
{
  "contributor_id": "0x...",
  "wallet_address": "4...xmr or tari address",
  "agreement_version": "1.0.0",
  "acceptance_timestamp": "ISO 8601 UTC",
  "contribution_id": "commit hash or platform ID",
  "signature": "ECDSA signature using contributor private key",
  "tari_nft_certificate": "Tari NFT minting transaction ID"
}
```

#### 5.4 Acceptance Database

All acceptance records will be stored in:
- Primary storage: Italian VPS database with GDPR-compliant encryption;
- Backup storage: Encrypted off-site backups within EU/EEA;
