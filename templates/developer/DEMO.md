# Demo Pilot — Developer

## Scenario
Uno sviluppatore entra in MyZubster e aiuta una community a trasformare un bisogno reale in una funzione digitale.

## Esempio
Un organizzatore di eventi richiede una pagina per pubblicare il noleggio del proprio sound system.

## Workflow
1. Il bisogno viene descritto in una issue.
2. Lo sviluppatore crea un fork.
3. Implementa la funzione su un branch dedicato.
4. Documenta setup e test.
5. Collega il servizio al profilo/Marketplace.
6. Apre una pull request verso MyZubster.

## KPI demo
- issue riproducibile
- fork funzionante
- test documentati
- PR revisionabile
- servizio utilizzabile dalla community
