# MyZubsterPilotKPI

A reusable framework for MyZubster smart-agriculture pilots that
defines baseline / pilot data models, a machine-readable KPI schema,
evidence / provenance tracking, and a reproducible baseline-vs-pilot
comparison report.

This is the implementation submitted for
[MyZubster-Ecosystem/myzubster Issue #533](https://github.com/MyZubster-Ecosystem/myzubster)
(*Pilot baseline, KPI & evidence framework 鈥?500 MYZ bounty*).

## Scope

The framework provides:

1. **KPI schema and machine-readable definitions** 鈥?covering water
   use, energy use, yield / output per area, nutrient / input
   efficiency, labour / time, sensor data uptime, anomaly
   detection-to-response time, and AI recommendation validation.
   See [`myzpkpi/kpi_schema.py`](myzpkpi/kpi_schema.py) and
   [`docs/kpi_schema.md`](docs/kpi_schema.md).
2. **Baseline data model** with a synthetic sample dataset that
   demonstrates baseline 鈫?intervention 鈫?comparison flow.
   See [`myzpkpi/baseline.py`](myzpkpi/baseline.py) and
   [`data/samples/records.csv`](data/samples/records.csv).
3. **Evidence / provenance format** capturing timestamp, source,
   method, unit, version and validation status for every
   measurement. See [`myzpkpi/evidence.py`](myzpkpi/evidence.py) and
   [`docs/evidence.md`](docs/evidence.md).
4. **Report generator** that produces a machine-readable JSON plus a
   human-readable Markdown comparison. See
   [`myzpkpi/report.py`](myzpkpi/report.py) and
   [`docs/methodology.md`](docs/methodology.md).
5. **Documentation** explaining assumptions, limitations, and how real
   pilot partners define their own final targets. See
   [`docs/`](docs/).
6. **Tests / validation** 鈥?66 unit tests covering computation,
   validation, missing / invalid data handling, evidence round-trip,
   and report guarantees. See [`tests/`](tests/).

## Quick start

```bash
# From a clean checkout, no dependencies are required at runtime.
# pytest is only needed to run the test suite.
python -m pip install pytest
python -m myzpkpi
```

The CLI writes two artefacts into `reports/`:

* `report.json` 鈥?full machine-readable comparison + disclaimers.
* `report.md` 鈥?human-readable Markdown summary.

Both artefacts use **only** the data shipped in `data/samples/`. Real
pilots supply their own CSV / JSON files via:

```bash
python -m myzpkpi \
  --records path/to/partner_records.csv \
  --evidence path/to/partner_evidence.json \
  --catalog data/config/kpi_catalog.json \
  --out-dir reports/
```

## Constraints respected

* Reproducible from clean checkout (zero runtime dependencies; pytest
  only for tests).
* Synthetic / non-sensitive sample data only 鈥?no production
  credentials or partner-identifying information.
* Units and formulas are documented in
  [`docs/kpi_schema.md`](docs/kpi_schema.md).
* The synthetic example walks through the full
  baseline 鈫?intervention 鈫?comparison 鈫?evidence report flow.
* The report never invents a percentage improvement; all numbers come
  directly from the input data via the documented formula.
* The framework makes no claim about funding from, endorsement by,
  or partnership with the European Commission, the EU LIFE
  programme, or any other public funder. This is asserted in the
  report's standard disclaimers.
* See [`docs/how_to_adopt.md`](docs/how_to_adopt.md) for guidance on
  adopting the framework in a real pilot.
