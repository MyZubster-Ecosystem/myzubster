# Join MyZubster

**Anyone can start contributing to MyZubster through the public GitHub workflow.**

You do not need a legal-name profile, KYC, cryptocurrency, a company affiliation, an invitation, or previous MyZubster experience to begin. You may use a public GitHub alias.

## Choose your path

### I am a developer
Pick an issue, reproduce a bug, improve tests, implement a focused change, or review a PR.

### I am a designer / illustrator / storyteller
Contribute original visual documentation, accessibility improvements, or a clearly labelled narrative/AI-assisted asset. Fiction must remain distinguishable from evidence.

### I am a photographer / mapper / field contributor
Submit only public or explicitly authorized observations and media using the documented evidence/privacy rules.

### I am a translator / writer
Improve documentation, translations, tutorials, onboarding or public explanations.

### I am a researcher / student
Review architecture, datasets, methods, assumptions and evidence. Clearly distinguish proposals from verified results.

### I am interested in privacy / Monero / settlement
Review or contribute to the documented external-settlement boundary. XMR settlement is separate from the internal MYZ accounting/reward layer and must be independently verified where applicable.

### I am completely new to open source
Start small: ask a question on an issue, fix a typo, reproduce a bug, improve a link or propose a character with `status: proposed`.

## Start here

1. Read [`CONTRIBUTING.md`](CONTRIBUTING.md).
2. Explore the public issues: https://github.com/MyZubster-Ecosystem/myzubster/issues
3. Comment on a task or ask a question before starting if anything is unclear.
4. Fork or branch the repository.
5. Submit a focused pull request with tests/evidence appropriate to the change.
6. Respond to public review.

## Create your character

Optional Character Registry:

https://github.com/MyZubster-Ecosystem/myzubster/issues/617

Your character may represent your public contributor alias and role. It is optional and does not represent KYC, employment, partnership, payment or ownership.

### Automatic Zorgax draft

When you enter the public contribution flow with a `CLAIM` or open a pull request, Zorgax may post an **optional character draft** using only your public GitHub alias and the contribution source.

Nothing is registered automatically. To opt in, reply to the Zorgax draft with exactly:

```text
ACCEPT CHARACTER
```

Zorgax will then add a `PROPOSED` character entry to Character Registry #617 with a provenance link to your consent/contribution. You can ignore the draft or write `SKIP CHARACTER` if you do not want a character.

See [`docs/ZORGAX_CHARACTER_AUTOMATION.md`](docs/ZORGAX_CHARACTER_AUTOMATION.md).

## What counts as contribution evidence?

Useful evidence can include, depending on the task:

- commit / PR links;
- reproducible tests;
- public issue discussion;
- approved documentation;
- authorized observation records;
- sanitized photos/media;
- public datasets;
- review results.

A PR, image or issue by itself does not automatically prove deployment, payment, adoption or partnership.

## Privacy and safety

Never submit passwords, credentials, wallet seeds, private keys, unnecessary private information, sensitive locations or data obtained through unauthorized access.

Security testing requires explicit authorization.
