# MyZubster: contributor journey, metaverse and GitHub character

This guide is for people who have opened an issue or pull request and want to understand the website, explore the metaverse and optionally create a public contributor character. **The website account, your GitHub account and a GitHub character proposal are separate things.**

## 1. Understand the project

MyZubster connects voluntary contributions, community projects, Zorgax assistance and public evidence. Start with [How MyZubster works](https://www.myzubster.com/come-funziona), [the main site](https://www.myzubster.com/) and the [visual story](https://www.myzubster.com/fumetto). A proposed character or illustration is storytelling; the issue, pull request and reviewed code or evidence show what actually happened.

The canonical code repository is [MyZubster-Ecosystem/myzubster](https://github.com/MyZubster-Ecosystem/myzubster). Daniel's current public GitHub contact is [danieldirimini-myzubster](https://github.com/danieldirimini-myzubster). The older `DanielIoni-creator` profile may return 404 to visitors. Existing issues and PRs under the organization keep their own URLs.

## 2. Enter MyZubster and Neon Plaza

1. Open [MyZubster sign-in](https://www.myzubster.com/social-login) and choose **Google** or **GitHub**. You do not need a paid plan to begin.
2. GitHub authorization has sometimes failed before returning to MyZubster. If it sends you to the GitHub home page or shows 404, use Google to enter the website and continue. This does **not** link a different GitHub account to your MyZubster profile. If your Google and GitHub emails differ, they may create separate site profiles; check the displayed username and email before publishing anything.
3. Open the [metaverse entrance](https://www.myzubster.com/metaverse). Choose the available guest path to explore or the account sign-in path for account features. A guest visit does not establish a verified GitHub identity.
4. To introduce yourself or ask for a suitable path, open [Zorgax](https://www.myzubster.com/zorgax). You can say: “I contributed to MyZubster as @YOUR_GITHUB_NAME in PR #NUMBER. Help me describe my skills and choose a mission.”

If sign-in fails, keep the URL and visible error text and share them in your existing GitHub issue or PR. Never post passwords, tokens or verification codes.

## 3. Create or edit your MyZubster profile

Open [profile onboarding](https://www.myzubster.com/zorgax-profile-onboarding.html) after signing in. Review what the page identifies as your account. Add only experience, interests and public links you choose to share. Zorgax may draft a short bio; review and edit it first. Saving on MyZubster and publishing to GitHub are different actions. GitHub publishing requires separate authorization and your explicit approval; it is not required for metaverse exploration or a code contribution.

Do not assume that entering a GitHub username in a field proves ownership of that GitHub account. If the verified GitHub connection is unavailable, continue with Google and your existing GitHub contribution link; do not create duplicate website profiles to work around the problem.

## 4. Optional GitHub character and comic profile

There are two different results:

- **Text character proposal:** If the project bot has posted a `Zorgax Character Draft` in your own issue or PR, inspect the alias and source. To opt in, reply **from the same GitHub account**, in that thread, with exactly `ACCEPT CHARACTER`. `SKIP CHARACTER` declines. The automated record is a **proposal** in the [Character Registry](https://github.com/MyZubster-Ecosystem/myzubster/issues/617); it does not automatically draw or publish a comic avatar.
- **Visual/comic character:** Follow [Character Registry issue #617](https://github.com/MyZubster-Ecosystem/myzubster/issues/617). In your fork, propose a manifest and an original visual (or a text-only character), link your public contribution and open a PR for review. Identify AI-generated art as such and include rights/provenance information. You can use a public alias; no legal name, health information or personal documents are required.

A character is optional. Being included in a story does not imply a verified legal identity, payment, project ownership or partner endorsement. Only approved work should be described as completed.

## 5. Continue contributing on GitHub

Open the [official repository](https://github.com/MyZubster-Ecosystem/myzubster), read [CONTRIBUTING.md](https://github.com/MyZubster-Ecosystem/myzubster/blob/main/CONTRIBUTING.md), and use your existing issue or PR to coordinate the next step. For code or documentation changes, fork, create a focused branch and open a pull request to `main` with verification details. [Existing issues](https://github.com/MyZubster-Ecosystem/myzubster/issues) remain readable; creating new issues is currently restricted, so use the relevant existing conversation when possible.

## In breve (italiano)

1. Leggi [come funziona MyZubster](https://www.myzubster.com/come-funziona) e usa il [repository ufficiale](https://github.com/MyZubster-Ecosystem/myzubster) per i contributi.

Per un'immagine originale o una storia visuale, segui [#617](https://github.com/MyZubster-Ecosystem/myzubster/issues/617) e invia una PR con la visual, la provenienza e il tuo consenso.
