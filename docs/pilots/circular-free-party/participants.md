# Participation Model

The pilot is open to developers and non-developers.

## Roles

- **Contributor** — proposes ideas, documentation, code, translations, design or research.
- **Resource provider** — offers reusable materials, equipment, skills, logistics or services.
- **Pilot operator** — runs a real-world test and records results.
- **Data steward** — helps collect evidence and KPI data.
- **Community connector** — links local communities, artists, makers, events or organizations.
- **Reviewer** — reviews GitHub issues and pull requests.

## How to participate

1. Create or use a GitHub account.
2. Open the MyZubster repository.
3. Fork the repository or open an issue.
4. Describe the resource, skill, problem or pilot idea.
5. Use a branch for your work.
6. Submit a Pull Request when the contribution is ready.
7. Link the contribution to a real-world pilot action when possible.
8. Record measurable outcomes in the KPI model.

## Contribution principles

- respect communities and cultural context
- do not claim affiliation with groups without permission
- document sources and decisions
- prefer reusable and open formats
- avoid unnecessary personal data
- use evidence for impact claims
- make participation possible for non-technical contributors

## GitHub contribution flow

**Identity -> Issue -> Fork/Branch -> Contribution -> Pull Request -> Review -> Pilot evidence**
