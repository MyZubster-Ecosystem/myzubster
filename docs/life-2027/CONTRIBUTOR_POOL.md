## Why this pool exists

The goal is to reuse real open-source skills already demonstrated in MyZubster rather than inventing project roles without evidence.

```text
PUBLIC GITHUB EVIDENCE
→ SKILL MATCH
→ CANDIDATE LIFE LANE
→ EXPLICIT OPT-IN / CLAIM
→ BOUNDED TASK
→ PR + TESTS / EVIDENCE
→ REVIEW
→ VERIFIED LIFE-ALIGNED CONTRIBUTION
```

## Opt-in format

A contributor who wants to participate should respond publicly with:

```text
LIFE INTEREST
GitHub username:
Preferred lane:
Relevant public contribution:
What I would like to help with:
Availability / first proposed task:
```

The maintainer should then route the contributor to an existing bounded issue instead of creating duplicate work.

## Institutional boundary

Institutional/scientific discussions and open-source contributor participation are separate evidence layers.

```text
OPEN-SOURCE CONTRIBUTOR
≠ UNIVERSITY REPRESENTATIVE
≠ COMPANY REPRESENTATIVE
≠ LIFE PARTNER
≠ CONSORTIUM MEMBER
```

A formal role requires explicit, independently verifiable agreement from the relevant person/organization.
