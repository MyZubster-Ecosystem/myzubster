# Come funziona MyZubster

MyZubster è un ecosistema open source che collega **mondo reale, GitHub, evidence, contributor, personaggi e storytelling visuale**.

Questa è la guida breve da leggere prima di iniziare.

## Il percorso in 30 secondi

```text
SCOPRI
  ↓
SCEGLI UNA MISSIONE
  ↓
CLAIM / PR
  ↓
CONTRIBUISCI
  ↓
REVIEW + EVIDENCE
  ↓
MERGE / STATO VERIFICATO
  ↓
PERSONAGGIO MYZUBSTER (opzionale)
  ↓
WORLD STATE / CHRONICLE
```

## 1. Scopri

Puoi iniziare dal sito, dal fumetto, dal repository o dalle issue pubbliche.

- Sito: https://www.myzubster.com
- Come funziona: https://www.myzubster.com/come-funziona
- Fumetto / Chronicle: https://www.myzubster.com/fumetto
- Repository: https://github.com/MyZubster-Ecosystem/myzubster
- Join: [`../JOIN.md`](../JOIN.md)

Non serve un invito privato per contribuire su GitHub. Puoi usare un alias pubblico.

## 2. Scegli una missione

Trova una issue compatibile con quello che sai fare oppure proponi una contribution piccola e verificabile.

Puoi partecipare come:

- sviluppatore;
- designer / illustratore;
- fotografo / mapper;
- traduttore / writer;
- ricercatore;
- tester;
- contributor AI, privacy, Monero, IoT, GIS o cybersecurity difensiva.

## 3. Fai CLAIM oppure apri una PR

Quando una issue richiede prenotazione, commenta `CLAIM` e descrivi brevemente lo scope.

Per una PR, mantieni il cambiamento focalizzato e collega issue, test o evidence rilevanti.

```text
ISSUE → CLAIM → DRAFT → PR → REVIEW
```

## 4. Zorgax propone il tuo personaggio

Quando il workflow rileva un nuovo `CLAIM` o una PR, Zorgax può preparare una **bozza personaggio** usando solo dati pubblici del contributo, per esempio:

- alias GitHub;
- ruolo tecnico o creativo provvisorio;
- issue / PR di origine;
- stato `PROPOSED`.

La bozza non diventa automaticamente un'identità MyZubster.

Per accettarla, il contributor deve scrivere:

```text
ACCEPT CHARACTER
```

Per non partecipare:

```text
SKIP CHARACTER
```

Il Character Registry è facoltativo: https://github.com/MyZubster-Ecosystem/myzubster/issues/617

## 5. Review ed evidence

MyZubster distingue sempre tra proposta, contributo e fatto verificato.

```text
Issue aperta        != missione completata
PR aperta           != contribution accettata
PR mergiata         != pagamento
Immagine AI         != evidence reale
Personaggio         != identità legale / KYC
Nome progetto esterno != partnership
```

La review controlla scope, qualità, test, provenance, privacy, sicurezza e claim.

## 6. Merge e World State

Quando un contributo viene accettato e mergiato, può entrare nel World State come evento pubblico e tracciabile.

Esempio reale del workflow visuale:

```text
BOUNTY #10
→ CLAIM @Aming9303
→ DRAFT
→ PR #12
→ REVIEW APPROVED
→ MERGE
→ METASPLOIT SENTINEL INTEGRATED
```

Il merge dimostra che la contribution è stata integrata nel repository. Non dimostra pagamento, partnership o deployment esterno.

## 7. Chronicle e visual

Gli eventi del progetto possono diventare capitoli visuali del fumetto MyZubster.

Esistono due classi principali:

- **FOTO REALE / EVIDENCE** — materiale reale collegato a record verificabili;
- **ILLUSTRAZIONE / CONCEPT** — storytelling, cyberpunk o AI-generated, sempre separato dalla prova.

Principio:

> **Fiction sopra, evidence sotto.**

## 8. Reward e settlement

MYZ è documentato come layer interno di reward/accounting. Un eventuale pagamento esterno, incluso XMR quando esplicitamente previsto, è un processo separato che richiede verifica indipendente.

```text
MERGE != PAID
REWARD_RECORDED != EXTERNAL SETTLEMENT
```

## 9. Privacy e sicurezza

Non pubblicare mai:

- password, seed o chiavi private;
- credenziali;
- informazioni private non necessarie;
- target di sicurezza non autorizzati;
- dettagli che facilitino accessi o exploitation non autorizzati.

Per la cybersecurity: solo attività difensive, autorizzate e tracciabili.

## Per iniziare adesso

```text
1. Apri JOIN.md
2. Scegli una issue
3. Scrivi CLAIM se richiesto
4. Contribuisci
5. Apri la PR
6. Rispondi alla review
7. Accetta il personaggio solo se lo vuoi
8. Entra nel World State quando l'evidence lo supporta
```

**MyZubster è costruito in pubblico: contribuisci, lascia provenance e non elevare mai un claim oltre la sua evidence.**
