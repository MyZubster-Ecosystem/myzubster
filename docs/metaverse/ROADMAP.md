# MyZubster Metaverse Roadmap

## Phase 0 — Neon Plaza prototype

- 2D/2.5D shared plaza
- guest avatar creator
- live presence
- movement
- chat
- emotes
- proximity awareness

## Phase 1 — MYZ identity integration

- merge and stabilize MYZ-DCR
- challenge/signature login
- verified MYZ-ID badge
- avatar ownership record
- signed character profile revisions
- revocation and key-rotation flow

## Phase 2 — Persistent social world

- accounts and sessions
- friends / follows
- private and public rooms
- persistent world objects
- MongoDB-backed profiles
- Redis-compatible distributed presence
- moderation, block, mute and report
- audit-safe event metadata

## Phase 3 — Personal comic identity

- personal comic timeline for every character
- verified contribution → story episode workflow
- canonical links to MyZubster Visual
- personal world / home space
- cross-character story events
- creator permissions and provenance metadata

## Phase 4 — 3D world

- Three.js/WebGL rendering
- customizable 3D avatars
- animated characters
- buildings and portals
- spatial zones
- mobile performance budgets
- optional WebXR support

## Phase 5 — Rich realtime interaction

- spatial voice using WebRTC
- party/group interaction
- collaborative building
- live events
- creator stages and exhibitions
- shared environmental simulations

## Phase 6 — Federation and portability

- portable identity credentials
- independently hosted MyZubster-compatible worlds
- signed world-to-world identity assertions
- decentralized or content-addressed asset storage where useful
- user-controlled export of character history and provenance

## Design principle

The metaverse must not make identity claims from usernames, display names or repository metadata. A character can be fun and pseudonymous; a verified identity badge must require explicit verifiable evidence.
