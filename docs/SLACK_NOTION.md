# MyZubster — Slack & Notion README

This document explains how Slack and Notion fit into the MyZubster contributor workflow.

## Start here

1. Discover MyZubster: https://myzubster.com
2. Read how it works: https://myzubster.com/come-funziona
3. Browse the GitHub organization: https://github.com/MyZubster-Ecosystem
4. Join Slack: https://join.slack.com/t/nuovaareadila-ml19359/shared_invite/zt-47dxpvwio-ZIkNdYv5Uk_glAilUiVnkg
5. Use the MyZubster Community Hub in Notion for durable documentation and status.

## Slack

Slack is the coordination layer, not the source of truth for code or evidence.

Main channels:

- `#myzubster-community` — onboarding and cross-project coordination.
- `#developers` — implementation, architecture, integrations and testing.
- `#visuals-content` — Visual Hub, characters, Chronicle and visual contributions.
- `#bounties-contributors` — mission and contributor coordination.
- `#life-2026-cnr-isof` — LIFE 2026 coordination.
- `#life-2026-partners` — partner coordination; keep sensitive correspondence private.

## Notion

Notion is the durable documentation layer for:

- onboarding and contributor guidance;
- policies and operational principles;
- ecosystem status;
- public/private boundaries;
- long-lived coordination notes.

GitHub remains authoritative for source code, issues, pull requests, technical evidence and provenance.

## Contributor workflow

```text
DISCOVER
  ↓
ISSUE / CLAIM
  ↓
CONTRIBUTE
  ↓
PULL REQUEST
  ↓
EVIDENCE / TEST
  ↓
REVIEW
  ↓
MERGE
```

Character onboarding is optional:

```text
CLAIM / PR
  ↓
ZORGAX CHARACTER DRAFT
  ↓
ACCEPT CHARACTER  (or SKIP CHARACTER)
  ↓
CHARACTER REGISTRY
  ↓
PROPOSED
  ↓
REVIEW / PROVENANCE
```

A GitHub alias or character is not KYC and does not establish a private/legal identity.

## Evidence rules

- A merge does not by itself prove payment, employment, partnership or production readiness.
- AI-generated visual/narrative material must remain distinguishable from real-world evidence.
- Do not publish credentials, sensitive personal data, private partner correspondence or real offensive-security targets.
- External brands/tools referenced by a character do not imply affiliation unless independently documented.

## Tool responsibilities

| Tool | Responsibility |
| --- | --- |
| GitHub | Code, issues, PRs, tests, evidence, provenance |
| Slack | People and fast coordination |
| Notion | Durable docs, policies and status |
| Google Drive | Shared working files and visual archive |
| MyZubster.com | Public discovery and intuitive entry point |

## Recommended onboarding

New contributors should join Slack, introduce themselves in `#myzubster-community`, select a small GitHub mission, post `CLAIM`, and keep implementation/review evidence attached to the relevant issue or PR.

Character creation is always opt-in. `ACCEPT CHARACTER` means the contributor wants the proposed public character registered; `SKIP CHARACTER` means no character should be created.
