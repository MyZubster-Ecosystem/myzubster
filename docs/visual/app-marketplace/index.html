INTEGRATION BOUNDARY

Gateway / Verifier

Authentication, orders and wallet-facing operations depend on configured Gateway contracts. External settlement remains independently verified.

App contracts

  • Authentication / orders
  • GET /api/wallet
  • GET /api/wallet/transactions
  • POST /api/wallet/address
  • POST /api/wallet/transfer

These are client-facing expectations documented in the App README, not proof that every endpoint is operational in production.

Marketplace areas

  • Garden CRUD and nearby queries
  • Sensor data ingestion
  • Latest sensor readings
  • Garden sensor statistics

Marketplace status is Development / active validation.

Native / privacy boundary

QR scanning/rendering and Orbot-related features may need native builds. Starting Orbot alone does not prove that all app traffic is routed through Tor.

Evidence boundary

Repository evidence supports DEVELOPMENT / ACTIVE VALIDATION.

Production release, live backend capability, external payment settlement and Tor routing each require separate runtime verification.

Guardrails: UI flow ≠ live backend · endpoint listed ≠ production availability · merge/bounty label ≠ external payment · app running ≠ Tor-routed traffic · internal MYZ ledger ≠ automatic on-chain settlement.
