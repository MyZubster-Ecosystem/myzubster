# MyZubster Contributor → Evidence → Verification Flow

> **Visual package #002 — Zorgax Visual Intelligence**

This visual documents the canonical contributor and bounty workflow described in [`BOUNTIES.md`](../../../BOUNTIES.md).

## Core principle

A bounty represents **verifiable work**, not an automatic payment promise.

```text
ISSUE / OBJECTIVE
      ↓
AUTHORIZED WORK
      ↓
EVIDENCE OR PULL REQUEST
      ↓
REVIEW + REQUIRED CHECKS
      ↓
VERIFIED | REJECTED
      ↓
REWARD_RECORDED
      ↓
EXTERNAL SETTLEMENT LIFECYCLE (WHEN APPLICABLE)
      ↓
PAID ONLY AFTER INDEPENDENT VERIFICATION
```

## Contributor flow

1. Read the issue and acceptance criteria.
2. Confirm the issue is active and unblocked.
3. Implement or collect only the authorized deliverable.
4. Submit the required evidence or pull request.
5. Wait for review and required checks.
6. If verified, the reward is recorded according to the bounty definition.
7. External settlement, when applicable, follows its own verification lifecycle.

## Important distinctions

```text
Issue created    ≠ work completed
PR opened        ≠ contribution accepted
PR merged        ≠ external payment
CID available    ≠ bounty satisfied
Reward recorded  ≠ blockchain transaction
Submitted tx     ≠ confirmed payment
```
