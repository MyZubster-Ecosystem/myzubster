Example mission path

  1. Discover / observe through App/Web or an authorized field workflow.
  2. Create mission / bounty context in the core repository or platform workflow.
  3. Attach evidence such as permitted media, metadata, telemetry or reproducible technical output.
  4. Optional specialist track: Marketplace, Robot, EVA IONI or Space Station may produce additional service/simulation/telemetry evidence.
  5. Review and verify against acceptance criteria. Repository existence or a PR alone does not prove completion.
  6. Publish sanitized state where appropriate through public snapshots/IPFS/IPNS.
  7. Record reward in MYZ only after the applicable verification gates.
  8. External settlement, if applicable, crosses Gateway → provider/treasury → independent verifier before any PAID claim.

Evidence boundaries

Cross-repository reference ≠ runtime integration. Shared documentation ≠ deployed API contract. Simulation ≠ physical execution. Internal MYZ reward ≠ external payment. Gateway submission ≠ settlement finality. A mission may stop at any stage if the required evidence does not exist.
