ZORGAX VISUAL #014 · RUNTIME EVIDENCE

Runtime / Deployment Evidence View

This view separates repository existence from actual runtime proof. A workflow file can describe validation logic; it does not prove that a deployment is currently healthy.

01 · SOURCE EXISTS

Repository, route, workflow or deployment configuration is publicly present.

02 · CI CHECKED

A named test/build/check has a recorded successful run for a specific revision.

03 · DEPLOY ATTEMPTED

A deployment workflow or provider records an actual deployment attempt.

04 · RUNTIME VERIFIED

A health/status endpoint or other live evidence is independently checked for a named environment and time.

05 · CONTINUOUSLY VERIFIED

Repeated checks show the runtime remains healthy over time; this is stronger than a single success.

Gateway example

The public deploy-production.yml defines tests, build, a public Zargox API check, optional Gateway health checks, optional VPS deployment, verification and rollback. This proves the validation/deploy logic exists in source. It does not, by itself, prove the latest run succeeded or that production is currently healthy.

Claim rules

SOURCE EXISTS may be supported by repository files. CI CHECKED requires a concrete workflow run/check result. DEPLOY ATTEMPTED requires a concrete deployment/run record. RUNTIME VERIFIED requires live/runtime evidence. A configured health check, provider URL, workflow name or README statement alone is not runtime proof.
