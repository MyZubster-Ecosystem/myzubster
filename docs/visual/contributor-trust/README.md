# Visual #019 — Contributor Trust / Verification Journey

This visual connects MyZubster's Character Registry, Proof-of-Contribution and security/trust rules into one contributor journey.

## Canonical journey

```text
ALIAS / CHARACTER
→ SCOPED LAWFUL CONTRIBUTION
→ EVIDENCE PACKAGE
→ INDEPENDENT VERIFICATION
→ VERIFIED CONTRIBUTION HISTORY
→ OPERATIONAL TRUST
→ OPTIONAL REWARD
→ ACTIVE VISUAL ROLE
```

## Source model

The journey is derived from:

- `docs/MYZ-PROOF-OF-CONTRIBUTION.md`
- `SECURITY.md`
- Character Registry issue #617 and the Visual Hub evidence model

## Trust rule

Trust is non-transferable and must remain separate from MYZ rewards. A token balance, character image, claimed skill, public alias or reputation label is not sufficient evidence of authority or competence.

A contributor may use a pseudonym. Where a high-value workflow requires stronger verification, that verification should avoid unnecessary public disclosure of personal information.

## Verification boundaries

- character/avatar != legal identity verification;
- GitHub account != proof of a unique human;
- PR submission != accepted contribution;
- evidence hash != truth of the complete claim;
- merged contribution != external payment;
- MYZ reward != authority or Trust Score;
- previous trust != authorization for a new security target;
- verifier status != permission to self-approve;
- `VERIFIED_CONTRIBUTOR` is evidence-bounded and contextual, not a universal certification.

## Human review

The view describes policy and evidence relationships. It does not automatically calculate or assign real contributor trust, identity status, security clearance or payment status.
