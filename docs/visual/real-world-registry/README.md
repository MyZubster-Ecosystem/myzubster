# Visual #015 — Registry / Real-World Observation

Evidence-first visual for the MyZubster observation/registry layer.

Canonical core workflow from the public README:

`OBSERVE → DOCUMENT → CONNECT → COLLABORATE → VERIFY → PUBLISH → REWARD / SETTLEMENT`

This view focuses on the observation-to-publication segment and keeps these boundaries explicit:

- media/file existence is not automatic verification of the real-world claim;
- a database/API registry row is application evidence, not physical truth;
- garden/sensor endpoints do not prove deployed or calibrated hardware;
- location data must be authorized and privacy-safe;
- publication or IPFS/IPNS references do not prove external settlement;
- MYZ remains an internal reward/accounting layer unless separately documented otherwise.

Primary public sources:
- `MyZubster-Ecosystem/myzubster/README.md`
- `MyZubster-Ecosystem/MyZubster-Marketplace/README.md`

Status represented here: **Core observations / mapping — Development / validation**.
