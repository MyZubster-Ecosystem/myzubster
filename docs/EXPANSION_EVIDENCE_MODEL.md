# MyZubster — Evidence-First Expansion Model

## Purpose

MyZubster is expanding through connected but distinct layers: open-source development, public contributors, environmental pilot preparation, LIFE 2027-aligned technical work, and scientific/operational stakeholder dialogue.

This document defines how that expansion is recorded without turning interest into unsupported claims.

## Expansion path

```text
MYZUBSTER CORE
      ↓
OPEN COMMUNITY
      ↓
SPECIALIZED CONTRIBUTORS
      ↓
VERIFIED PUBLIC CONTRIBUTIONS
      ↓
ENVIRONMENTAL PILOT PREPARATION
      ↓
OPTIONAL LIFE 2027-ALIGNED TECHNICAL TRACK
      ↓
SCIENTIFIC / OPERATIONAL STAKEHOLDER DIALOGUE
      ↓
AUTHORIZED PILOT
      ↓
REPRODUCIBLE EVIDENCE
```

The layers can develop in parallel, but stronger status must always be supported by stronger evidence.

## Evidence ladder

```text
INTEREST
  ↓
CONTRIBUTION
  ↓
VERIFIED CONTRIBUTION
  ↓
EXPLICIT COLLABORATION
  ↓
AUTHORIZED PILOT
  ↓
FORMAL PARTNERSHIP / CONSORTIUM ROLE
```

Do not skip levels in public descriptions.

### Interest
Examples: issue comment, `CALL INTEREST`, `LIFE INTEREST`, request to work on a task.

Interest proves only that a person publicly expressed interest.

### Contribution
Examples: PR, code, tests, documentation, design, dataset preparation or reproducible technical work.

A contribution does not automatically imply employment, payment, partnership or future availability.

### Verified contribution
A contribution has been reviewed against explicit acceptance criteria and has attributable public evidence.

### Explicit collaboration
A contributor or external actor has explicitly agreed to a defined collaborative activity. The exact scope and evidence should be recorded.

### Authorized pilot
A real-world pilot requires explicit authorization, appropriate data governance, defined roles, measurable baseline/KPIs and evidence rules.

### Formal partnership / consortium role
This status must be supported by an explicit agreement or other appropriate formal evidence. GitHub participation, a meeting, an email exchange or a technical contribution is not sufficient by itself.

## Active contributor → LIFE-aligned track

Active MyZubster contributors with relevant, verifiable public work may **opt in** to the LIFE 2027-aligned technical preparation track.

Candidate lanes include:

- API / backend / data pipeline;
- database and mapping;
- GIS / geospatial data;
- IoT / environmental sensing;
- KPI / MRV / evidence workflows;
- dashboard and evidence UX;
- QA / reproducibility / automated testing;
- automation safety and human review;
- replication documentation.

Activation path:

```text
PUBLIC GITHUB EVIDENCE
→ LIFE INTEREST / OPT-IN
→ CANDIDATE TECHNICAL LANE
→ BOUNDED ISSUE
→ PR / TEST / DOCUMENTED OUTPUT
→ REVIEW
→ VERIFIED LIFE-ALIGNED CONTRIBUTION
```

Participation in this track does **not** by itself imply LIFE funding, EU/CINEA endorsement, employment, institutional affiliation, consortium membership, partnership or guaranteed reward/payment.

## Stakeholder dialogue

Scientific, university, business, public-sector or operational actors may participate in exploratory discussions around pilot design, methodology, data, KPIs, MRV, replication and implementation constraints.

Meeting attendance or technical feedback should be recorded as exactly that. It must not be upgraded to partnership, endorsement or consortium membership without explicit evidence.

## System rule

MyZubster should be able to answer each public status claim with:

1. **What happened?**
2. **Who explicitly participated?**
3. **What public or authorized evidence supports it?**
4. **What level of the evidence ladder does it reach?**
5. **What stronger claim is still not justified?**

## North-star rule

> Expansion is not measured only by repository count, issue count or meeting count. It is measured by independently inspectable progress from interest to verified contribution, from verified contribution to authorized pilot, and from pilot to reproducible evidence.
