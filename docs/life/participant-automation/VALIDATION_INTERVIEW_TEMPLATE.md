# Validation interview template

Usare almeno quattro risposte individuali. Il partecipante può raccoglierle, ma nel repository devono apparire soltanto etichette anonime.

## Istruzioni per il partecipante

- Presenta le idee senza promettere vendite o risultati.
- Non raccogliere nomi, email, telefoni, indirizzi o dati sensibili.
- Non unire due persone in una risposta.
- Identifica sempre l'idea con il suo `candidateId`.
- Riporta anche risposte negative o dubbi.

## Scheda da ripetere quattro volte

**Persona:** `A / B / C / D`  
**Candidate ID:** `[candidate-id]`  
**Idea preferita:** `[candidate-id or none]`

1. Perché useresti o non useresti questa idea?
2. Quale problema concreto dovrebbe risolvere?
3. Come risolvi oggi questo problema?
4. Quale risultato vorresti ottenere entro sette giorni?
5. Quale funzione o contenuto è indispensabile?
6. Proveresti gratuitamente una prima versione? `sì / no / forse`
7. Valuteresti un'offerta futura? `sì / no / non chiesto`
8. Quale dubbio o rischio ti impedirebbe di provarla?

## Gate di completezza

Una risposta è `COMPLETE` soltanto se appartiene a una persona, indica un candidate ID e contiene problema, soluzione attuale, risultato desiderato, funzione indispensabile e disponibilità al test.

Il ranking resta invariato se una o più risposte sono raggruppate, non attribuibili o incomplete.
