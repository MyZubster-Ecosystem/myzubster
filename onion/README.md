# MyZubster Onion Service

This component runs a Tor v3 Onion Service as an isolated Docker container and forwards HTTP traffic to the internal `frontend` service.

## Architecture

```text
Internet
   |
  Tor
   |
   v
myzubster-onion :80
   |
   v
frontend:3000 (Docker network only)
```

## Start

```bash
docker compose up -d --build
```

The Onion hostname is generated by Tor inside the persistent `onion_data` volume. The hostname can be read from the running container without exposing the private key:

```bash
docker compose exec onion cat /var/lib/tor/myzubster/hostname
```

## Identity and security

- The Onion service uses a persistent volume so its v3 identity survives container recreation.
- The Tor SOCKS port is disabled (`SocksPort 0`).
- The Onion container is not published to the host; traffic reaches it through Tor and the Docker network.
- The private Onion key remains inside the persistent volume and must never be committed to Git.
- Rotate/delete `onion_data` only when intentionally rotating the Onion identity.

## Production notes

This is an initial infrastructure implementation, not a production security certification. Before production use, add resource limits, read-only filesystem hardening where compatible with Tor, health checks, backup/restore procedures for the Onion identity, and an external security review.
