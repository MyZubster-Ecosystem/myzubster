# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take security vulnerabilities seriously. Please report them through our **private vulnerability reporting channel**:

- **Email**: security@myzubster.com
- **PGP Key**: [security@myzubster.com.asc](security@myzubster.com.asc)
- **GitHub Security Advisories**: Use the "Report a vulnerability" tab

**Do not** create public issues for security vulnerabilities.

## Bounty Program

We operate a security bounty program. See [Bounty Program Documentation](docs/security/bounty-program.md) for:
- Eligible assets and environments
- Rules of Engagement
- Reward structure and governance
- Triage workflow
- Safety controls

## Response Timeline

- **Acknowledgment**: Within 48 hours
- **Initial Assessment**: Within 5 business days
- **Status Updates**: Every 7 days until resolution
- **Resolution Target**: 30 days for Critical/High, 90 days for Medium/Low

## Disclosure Policy

We follow coordinated disclosure. We will:
1. Work with you to understand and reproduce the issue
2. Develop and test a fix
3. Coordinate a disclosure timeline (typically 30-90 days after fix)
4. Publish a sanitized advisory crediting you (if desired)

## Scope

### In Scope
- Core application (web, mobile, API)
- Smart contracts (if applicable)
- Infrastructure configuration
- Authentication/authorization systems

### Out of Scope
- Third-party services not operated by us
- Social engineering attacks
- Physical security
- Denial of Service (DoS) attacks
- Issues requiring destructive testing

## Safe Harbor

We authorize testing in accordance with our [Rules of Engagement](docs/security/rules-of-engagement.md) and will not pursue legal action for good-faith research that follows these rules.
