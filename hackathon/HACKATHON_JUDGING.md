# 🏆 Hackathon Judging Criteria

This document outlines how projects will be evaluated during MyZubster Hackathon 2026.

## 📊 Scoring Overview

| Criteria | Weight | Max Points |
|----------|--------|------------|
| Innovation | 25% | 25 |
| Technical Excellence | 25% | 25 |
| Impact | 25% | 25 |
| Presentation | 15% | 15 |
| Community | 10% | 10 |
| **Total** | **100%** | **100** |

---

## 🎯 Detailed Criteria

### 1. Innovation (25 points)

| Score | Description |
|-------|-------------|
| 21-25 | Revolutionary approach, completely novel solution |
| 16-20 | Creative solution, significant improvements |
| 11-15 | Good ideas, some original thinking |
| 6-10 | Basic implementation, minor innovations |
| 1-5 | Minimal innovation, standard approach |

**Questions judges will ask:**
- Does this solve a real problem in gardening?
- Is the approach unique or creative?
- Would this inspire others to build similar things?

### 2. Technical Excellence (25 points)

| Score | Description |
|-------|-------------|
| 21-25 | Clean code, excellent architecture, well-tested |
| 16-20 | Good code quality, solid architecture |
| 11-15 | Working code, reasonable structure |
| 6-10 | Functional but needs refinement |
| 1-5 | Basic implementation, technical issues |

**Evaluation factors:**
- Code readability and organization
- Error handling and edge cases
- Performance and efficiency
- Test coverage
- Documentation quality

### 3. Impact (25 points)

| Score | Description |
|-------|-------------|
| 21-25 | Could help millions of gardeners worldwide |
| 16-20 | Significant impact for a large community |
| 11-15 | Helpful for many gardeners |
| 6-10 | Useful for some users |
| 1-5 | Limited practical impact |

**Considerations:**
- How many people could benefit?
- Does it solve a common pain point?
- Is it accessible to different skill levels?
- Does it promote sustainable gardening?

### 4. Presentation (15 points)

| Score | Description |
|-------|-------------|
| 13-15 | Compelling demo, clear explanation, professional |
| 10-12 | Good demo, understandable presentation |
| 7-9 | Adequate demo, basic explanation |
| 4-6 | Minimal demo, unclear explanation |
| 1-3 | No demo or very poor presentation |

**Presentation checklist:**
- [ ] Working demo or screenshots
- [ ] Clear problem statement
- [ ] Solution explanation
- [ ] Future roadmap
- [ ] Q&A handling

### 5. Community (10 points)

| Score | Description |
|-------|-------------|
| 9-10 | Helped many others, active in community |
| 7-8 | Assisted other teams, participated in discussions |
| 5-6 | Some community engagement |
| 3-4 | Limited interaction |
| 1-2 | No community involvement |

**Community activities:**
- Helping other participants
- Answering questions in Discord
- Reviewing other PRs
- Sharing knowledge and resources

## 🎭 Judging Panel

| Judge | Role | Focus Area |
|-------|------|------------|
| Lead Judge | Core maintainer | Technical excellence |
| AI Expert | ML researcher | AI/ML implementation |
| UX Designer | Product designer | UI/UX quality |
| Community Lead | Community manager | Community impact |

---

## 📝 Judging Process

### Phase 1: Initial Review (Day 6-7)
- All submissions reviewed
- Technical validation
- Demo testing

### Phase 2: Scoring (Day 7)
- Individual judge scoring
- Score compilation
- Conflict resolution

### Phase 3: Deliberation (Day 7)
- Top 3 finalists per track
- Final discussion
- Winner selection

### Phase 4: Announcement (Day 7)
- Live presentation
- Winner announcement
- Prize distribution

---

## ⚖️ Fair Play Rules

1. **Original Work:** All code must be written during the hackathon
2. **Open Source:** Submissions must be MIT or Apache 2.0 licensed
3. **No Plagiarism:** Properly attribute any referenced work
4. **Team Size:** Maximum 4 members per team
5. **One Submission:** Each team can submit to one track only

---

## 🤔 Disqualification Criteria

- Plagiarism or copyright infringement
- Pre-existing code presented as new
- Inappropriate or offensive content
- Violation of Code of Conduct
- Missing submission deadline
