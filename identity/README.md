## Identity Bounty Program

The **MyZubster Identity Bounty Program** rewards independent work that makes this technical identity easier to verify, harder to impersonate and more transparent to external partners.

All rewards in this identity program are denominated **exclusively in MYZ**. Under the current MyZubster platform model, MYZ is an internal reward/accounting unit. A reward marked as approved or recorded does not by itself prove an on-chain transfer or fiat payment.

The detailed rules are in [`BOUNTY.md`](./BOUNTY.md), the machine-readable challenge list is in [`challenges.json`](./challenges.json), and completed/approved rewards are tracked in [`rewards.json`](./rewards.json).

### How it works

1. **Choose an open bounty.** Open identity bounties are published as GitHub Issues and mirrored in `challenges.json` with a stable identifier such as `ID-BNT-0001`.
2. **Read the objective and acceptance criteria.** The reward is earned only when the submitted work satisfies the stated criteria; merely opening a PR, issue or comment is not sufficient.
3. **Work only inside authorized scope.** Contributors must not access third-party systems without permission, collect unnecessary personal data, steal credentials, perform destructive testing or publish sensitive security details prematurely.
4. **Submit reproducible evidence.** Depending on the bounty, evidence may be documentation, deterministic verification steps, tests, code, a pull request or a private security report.
5. **Maintainer review.** MyZubster reviews the submission against the bounty criteria. Security-sensitive findings may require private review before any public disclosure.
6. **Verification decision.** A valid contribution moves through review to `VERIFIED`; invalid or incomplete submissions may be rejected or returned for changes.
7. **MYZ reward accounting.** Once approved, the corresponding MYZ reward is recorded in the program ledger. Public reward records should avoid unnecessary personal information.

A simplified lifecycle is:

```text
OPEN
  -> CLAIMED / IN PROGRESS
  -> SUBMITTED
  -> UNDER REVIEW
  -> VERIFIED | REJECTED
  -> REWARD RECORDED (MYZ)
```

### What contributors must never publish

Do **not** commit or post private keys, seed phrases, passwords, authentication tokens, government identity documents, SPID/CIE credentials, private security exploit details before remediation, or personal data that is not necessary for verification.

The purpose of the program is to improve **technical verifiability and impersonation resistance**, not to crowdsource or expose sensitive identity documents.
